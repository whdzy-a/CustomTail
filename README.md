# CustomTail

把玩家的尾巴当成一张**网格**来改：尾巴本身仍由游戏绘制，模组在它上面"焊"额外的点、线、三角形。

- 尾巴**完全用游戏数据构建**：节数、半径、连接距离都取自 `PlayerGraphics` 里的 `TailSegment` 参数，
  运动照抄 `ReactPlayer` 的尾巴更新循环（重力、链式拉力、`connectionRad` 限制）。
- 装饰是**依附于尾巴的点线三角形结构**：可以加点、连线、连三角形，随时增删。
- 点可以**绑定**到尾巴某一节的某个位置、另一个点、或者某条线上的百分比处。
- 线可以是**刚体**（`stiffness = 1`，长度逐帧强制保持）或**弹性**（`0 < stiffness < 1`，会被重力拉开）。

> 想按「我想干什么」快速查所有能按 / 能拖 / 能改的地方，见 **[操作总表.md](操作总表.md)**（游戏内 · 菜单 · 配置 · 文件 · 编辑器 · 工具 · 日志，九个系列，逐项核对过代码）。

## 尾巴是怎么"由游戏数据"来的

游戏里尾巴是 4 个 `TailSegment`：

| 节 | rad | connectionRad | affectPrevious |
| --- | --- | --- | --- |
| 0 | 8 | 4 | 1 |
| 1 | 6 | 3.5 | 0.5 |
| 2 | 4 | 3.5 | 0.5 |
| 3 | 2 | 3.5 | 0.5 |

每帧（`PlayerGraphics.Update`）：先 `TailSegment.Update()`（位置积分、超过 `connectionRad` 就把自己和上一节互相拉近），
再乘空气阻尼、加法向重力、用 `9*(i+1)` 限制离髋距离、再用前两节的连线方向补一个拉力。
编辑器完整复刻了这一套，所以你看到的尾巴形状就是游戏里的形状。

## 尾巴网格顶点（`tvert`）

编辑器把尾巴看成一条长条三角形网格，编号规则和 `TriangleMesh.MakeLongMesh` 一样：**每个站点 2 个顶点**，
索引 `2k` / `2k+1`（`2k` 在站点方向的负法向一侧，`2k+1` 在正法向一侧，三角形是 `(2k,2k+1,2k+2)`、`(2k+1,2k+3,2k+2)`）。

| 站点 k | 顶点 | 含义 | 宽度 |
| --- | --- | --- | --- |
| 0 | 0 / 1 | 尾根 `(hips*3+body)/4`，不是 `TailSegment` | 固定 6 |
| 1 | 2 / 3 | 游戏 `TailSegment` 0 | `rad * clamp(connectionRad / 与上一站距离, .2, 1)` |
| 2 | 4 / 5 | `TailSegment` 1 | 同上 |
| 3 | 6 / 7 | `TailSegment` 2 | 同上 |
| 4 | 8 / 9 | `TailSegment` 3（尾巴尖，两点重合） | 0，用来收口 |

这 10 个顶点位置**只由游戏尾巴决定**：编辑器里它们只读——不能拖动、不能删除、不能连线，只能当绑定目标；
点中它们会提示"只能被绑定"。绑定写成 `bind.kind = "tvert"` + `bind.v = <0..9>`，游戏侧
`MeshRuntime.TailMeshVerts()` 用同一套公式算出同一个顶点，所以是精确贴合而不是"接近"。

## 三角形与贴图（`triangles` / `textures`）

编辑器能直接造三角形并对「三角形组」套贴图，模型对齐游戏里的 `TriangleMesh`。

**整组一张图**：同一组的三角形共用一张贴图，图会**整块变形覆盖整组**（不是每个三角形各铺一遍）。
这是靠**逐顶点 UV** 实现的，和 `TriangleMesh.UVvertices` 的做法一致：

- 组有一个**映射范围** `rect = [x, y, w, h]`（世界坐标）。默认不写进 JSON，等于"自动贴合组内节点的静止包围盒"；
- 每个顶点按它在范围里的归一化位置取 UV：`u = u0 + (u1-u0)·fx`、`v = v0 + (v1-v0)·fy`
  （`fx,fy` = 顶点 rest 在 rect 里的比例，所以左→u0、右→u1、下→v0、上→v1）；
- 三角形内部按三个顶点的 UV 做仿射插值 —— 与 GPU 逐顶点插值等价；
  相邻三角形的**公共顶点 UV 相同**，所以整组是连续的一张图，没有接缝、也不会重复；
- UV 用的是节点的 **rest（静止位置）**，物理形变时贴图不会在三角形里"游动"；
  用「选择/拖动」改形状（会更新 rest）时贴图会跟着重新贴合。

面板操作：

- **三角形工具**：按顺序点 3 个点成一个三角形；
- **选择工具**点三角形内部 = 选中；**Ctrl+点击** = 加选/取消，凑出一组；
- 右侧填 `element`（图集里的 sprite 名，如 `Futile_White`）+ UV 矩形 `u0,v0,u1,v1`（**原点左下**，和游戏 `uvRect` 一致），
  点「套用到选中的 N 个面」→ 这些三角形共用同一个贴图对象 = 同一组；参数一模一样的会**自动复用**成同一组；
- **UV 不限于 0–1**：滑块轨道只到 0–1，但右边的数字框可以直接输更大的值（比如 `1.5`、`-0.25`）。
  超出 element 的那部分会采到图集里**相邻的像素**（游戏端是线性换算 `element.uvRect + uv·size`，不夹取），
  适合"蹭边上的一块""整张纹理平铺"这类用法；不想采到别人就把 UV 收回 0–1；
- 「套用到选中的面」挂的是**面板里正在编辑的那张**（新组时是一张草稿），所以在点击之前改的
  UV / element / 映射范围都会保留；
- **映射范围**：默认「自动贴合组包围盒」；关掉后就锁定成 `rect`，可以填 `X/Y/W/H` 手动拉伸/偏移
  （比如把图横向拉宽 2 倍），或点「按当前形状重设范围」。锁定值才会写进 JSON 的 `rect`；
- 选中一组时，面板改的参数**立刻生效**；跨多个组时改的是暂存值，点「套用」才写进去（也可以用来把几组并成一组）；
- `SetAtlasedImage` 开关（JSON 里的 `atlas`）：`true` = UV 相对该 element（渲染时用 `element.uvRect` 换算到图集空间），
  `false` = UV 当整张图集的 0–1 坐标直接用（想精确抠图集某块时用）；
- 面板里可以载入一张**本地图片**做预览（只在编辑器里按这套 UV 显示，**不进 JSON**）。

渲染侧：每个贴图组一个 `TriangleMesh`（3 顶点/三角形，顶点位置每帧从绑定解算后的节点位置写入），
UV 在创建时按 `rest` + `rect` 算好写进 `UVvertices`（缺 `rect` 时用 `MeshRenderer.GroupFrame()` 自动算包围盒，
公式与编辑器 `fitRect()` 保持一致）；没有三角形的文档仍然走老的"每条边一个四边形"路径，旧 JSON 不受影响。

## 角度约束（`angles`）

选中**一个角点 + 另外两个点**，就给这三点加一条夹角约束：`∠(a-c-b) = deg`。

- **工具**：左栏「角度（A）」—— 先点**角点**，再点两条边的**端点**（3 次点击）。新建时把当前角度存成目标，所以刚建好不会跳。
- **属性**：右侧可改 `目标角度`（-179..179°）、`刚度`（1 = 刚性，越小越软）、`宽度`；
  「用当前角度当目标」把眼下这个角度固化下来，「删除角度」删掉约束。
- **解算**：把 a、b 绕 c 旋转（两个端点都自由时各转一半；只有一端自由就全给它；两端都被绑定则该约束无解）。
  **只旋转、不改边长** —— 单测里验证过 A/B 到 C 的距离在求解前后完全一致。
- **视觉**：以 c 为心、从 `c→a` 的射线扫到 `c→b` 的圆弧，两端各带一小段径向刻度，
  配色/虚线（弹性）/选中高亮/层显隐/前后分层都和**线**完全一致；选中时弧外显示目标角度。
  这样"从一条线的方向开始、到另一条线的方向结束"，看起来就是线上的一个量角器。
- **JSON**：

```json
"angles": [ { "c": "n0", "a": "n1", "b": "n2", "deg": 60, "stiffness": 1, "width": 1.6 } ]
```

`deg` 是度（正 = 从 `c→a` 逆时针转到 `c→b`）；也可以写弧度的 `angle` / `target`，解析器会自动换算。
游戏端 `MeshInstance.SolveAngles()` 用同一套旋转解算，所以导出的角度在游戏里也生效。

### 受力方式：正常 / 仅拉力 / 仅推力

线和角度都有「受力方式」，决定这个约束**只在哪个方向上出手**：

| 方式 | 线（两点的距离） | 角度（`∠a-c-b`） | 画布上的箭头 |
| --- | --- | --- | --- |
| **正常**（缺省） | 拉长/压短都纠正 | 撑大/收回都纠正 | 不画 |
| **仅拉力** | 只在被**拉长**时把两端拉近（像绳子） | 只在角度**被撑得太大**时把两端收回 | 两只箭头**朝里**，琥珀色 |
| **仅推力** | 只在被**压短**时把两端推开（像撑杆） | 只在角度**被挤得太小**时把两端撑开 | 两只箭头**朝外**，蓝色 |

箭头就是"现在这个约束想往哪使劲"：**朝里 = 拉、朝外 = 推**。亮着的箭头 = 眼下确实在吃这个方向的力
（线被拉长 / 角度被撑大或压小），暗一点 = 这个约束现在不管这个方向。

<img src="editor/ui-preview-force.png" width="560" alt="受力箭头：横线仅拉力（琥珀、朝里）、竖线仅推力（蓝、朝外）；左边的角仅拉力、右边的角仅推力">

（上图：下面那条横线是**仅拉力**、正在被拉长 → 琥珀箭头朝里；左边竖线是**仅推力**、正在被压短 → 蓝色箭头朝外；
左下那个角**仅拉力**、角度正被撑大 → 箭头沿弧朝里；右边那个角**仅推力**、角度正被压小 → 箭头沿弧朝外。）

- 选一条线 / 一个角度，左栏「受力方式」里三选一；改一下就是一步撤回。
- 线/角度列表里颜色不变，只有非「正常」的才画箭头 —— 正常约束看起来和以前完全一样。
- JSON 里只在非正常时写 `"mode": "pull"` / `"mode": "push"`（旧文件不受影响）。
- 游戏端同一套判据（`MeshInstance.ForceAllows`）：线看 `distance − rest`，角度看 `当前角 − 目标角`，
  `> 0` 才允许"拉"、`< 0` 才允许"推"。`tooling/AngleCheck` 里有对应的单测。

> 关于命中：**被隐藏的对象不会被选中** —— 点/线/面/sprite/角度都会按「图层显隐 + 顶栏 点/线/面 开关」拦住；
> 只有尾巴网格顶点是例外（它是参考手柄而不是可编辑对象，顶点框默认关着，但绑定和施力随时要点它）。
## JSON 格式

```json
{
  "schema": 5,
  "color": "#ffffff",
  "physics": { "gravity": 0, "iterations": 8, "damping": 0.02, "tailRoll": 0.35 },
  "nodes": [
    { "id": "n0", "rest": [3.7, -8.5],
      "bind": { "kind": "tvert", "v": 4, "local": [0.5, 1.2] }, "offset": [0.5, 1.2] },
    { "id": "n1", "rest": [3.6, -13.3],
      "bind": { "kind": "tail", "segment": 2, "t": 0.5, "local": [4, -2] }, "offset": [4, -2] },
    { "id": "n2", "rest": [10.6, -15.1], "bind": { "kind": "free" } }
  ],
  "links": [
    { "a": "n0", "b": "n2", "stiffness": 1, "width": 2, "rest": 7.3 },
    { "a": "n1", "b": "n2", "stiffness": 1, "width": 2, "rest": 6.1 }
  ],
  "textures": [
    { "element": "Futile_White", "uv": [0.1, 0.2, 0.9, 0.8], "atlas": true }
  ],
  "triangles": [
    { "v": ["n0", "n1", "n2"], "tex": 0 }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `schema` | 现在导出 `5`；解析器 = `5`，同时接受旧的 `edges` 与数组形式的 `color` |
| `color` / `alpha` | `"#rrggbb"` 或 `[r,g,b]`（0–1），`alpha` 缺省 1 |
| `bind.kind` | `free`（自由点）、`tvert`（尾巴网格顶点 `v` 0–9）、`tail`（尾巴 `segment` 节的 `t` 处）、`node`（刚性跟随 `a` 点）、`edge`（落在 `a`–`b` 线的 `t` 处） |
| `bind.local` | 尾巴局部系偏移 `[沿尾, 垂直]`，会跟着尾巴旋转；`tail` / `tvert` 都支持 |
| `offset` | 世界偏移（老格式，保留兼容；有 `local` 时以 `local` 为准） |
| `rest` | 编辑时的位置；边的静息长度按两端 `rest` 的距离算 |
| `stiffness` | `1` = 刚体，越小越软 |
| `links` | 边只参与求解；没有 `triangles` 时渲染器按每条边一个四边形铺面（旧字段名 `edges` 仍然认）；可选 `mode`：`"pull"` 仅拉力 / `"push"` 仅推力，缺省 = 正常 |
| `angles` | 三点夹角约束：`c` 角点、`a`/`b` 两端、`deg` 目标角（度）、`stiffness`、`width`；游戏端 `SolveAngles()` 会真的解它；同样支持 `mode` |
| `textures` | 贴图组：`element` + `uv:[u0,v0,u1,v1]` + `atlas` + 可选 `rect:[x,y,w,h]`（映射范围，缺省=自动贴合组包围盒） |
| `triangles` | 要画的面：`v:[a,b,c]` 是三个点的 id，`tex` 指向 `textures` 的下标（`-1` = 纯色） |
| `sprites` | 自由贴图（不贴三角形）：`pos`/`dir` 指向点、`anchor:[u,v]`、`scale:[sx,sy]`、`angle`、`order`(绘制顺序)、`tex`、可选 `noRoll`（不跟随滚转）；**`scale` 可以为负 = 镜像**，`0` 会按 `1` 读 |
| `physics.tailRoll` | 整条尾巴的滚转 `-1..1`，见「滚转」一节；缺省 0 = 不滚，和旧文件完全一致 |

## 图集：直接挑游戏里的 sprite

编辑器右侧有个 **图集** 页签，可以按名字搜索、看缩略图、点一下就把那个 sprite 套到选中的三角形上。
数据来自三处，全部由 `tooling/atlas_dump.py` 一次性导出：

| 来源 | 实际文件 | 说明 |
| --- | --- | --- |
| 本体 | `RainWorld_Data/resources.assets` 里的 `Texture2D` + 同名 `TextAsset` | `rainWorld`（620 个，身体/尾巴/头部都在这里）、`uiSprites`、`rainworldmsc`、`regionGate`… |
| 模组 | `StreamingAssets/mods/*/atlases/*.txt` + 同名 `*.png` | TexturePacker 的 hash 格式，element 名 = 帧名去掉 `.png` |
| AB 包 | 任意 `*.bundle` / `*.assets` 里的 `Sprite` / `Texture2D` | 含 `aa/StandaloneWindows64/*.bundle`；有 `Sprite` 就用它的 `rect`（精确到每个 sprite），否则整张贴图当一个 |

用法：

```bash
pip install UnityPy                              # 只需要一次
python tooling/atlas_dump.py                     # 自动找 Steam 里的雨世界
python tooling/atlas_dump.py --game "D:/.../Rain World"
python tooling/atlas_dump.py --all               # 连字体图集（8192×2048）也导
python tooling/atlas_dump.py --no-mod --no-bundle # 只导本体
```

产物写到 `editor/atlas-cache/`：`atlas-pack.js`（编辑器启动时用 `<script>` 自动载入，不需要联网、
不需要本地服务器）+ `png/` + `index.json`。这套机制绕开了 `file://` 下 `fetch` 被禁的问题：
脚本能加载、`<img>` 能加载，只有 `fetch/XHR` 不行。删掉整个 `atlas-cache/` 编辑器照样能用，只是图集页签是空的。

没跑脚本也能用：图集页签里点 **「载入图集文件夹…」** 直接选 `StreamingAssets/mods`（或某个模组的 `atlases` 目录），
选中的 `*.txt` + 同名 `*.png` 会被解析；也可以选任意 `index.json`。

挑中的 sprite 会写成：

- `element` = sprite 名（游戏侧 `Futile.atlasManager.GetElementWithName` 用的就是这个名字，不带 `.png`）；
- `uv` = `[0,0,1,1]`、`atlas = true` —— 也就是"整个 element"，gpu 侧由 `SetAtlasedImage` 换算到图集空间；
- 编辑器自己额外记 `lat / ar / px`（哪个图集、在贴图里的 uv 矩形、像素尺寸）**只用于预览，不写进 JSON**。

所以导出的 JSON 和手填 element 完全一样，旧文件也能正常打开；打开时编辑器会按 `element` 名把贴图重新挂上。

> `atlas-cache/` 是开发期缓存（约 2 MB）。发布模组前可以删掉，或加进忽略列表。

### 临时图集：插入 PNG / 打开图集 / 自动排版

图集页签最上面是 **临时图集**：不用跑 `atlas_dump.py`，自己画 / AI 生成 / 从别处拆出来的 PNG
可以直接当图集用，几张图凑成一张、改完导出成游戏能读的 `<名字>.png` + `<名字>.txt` 两个文件。

1. **插入 PNG…** —— 可以**一次选多张**：每张图贴到画布上、自动生成一个同名 sprite
   （同名的自动加 `_2`、`_3`），然后立刻跑一次自动排版；
2. **打开图集…** —— 选一对同名的 `xxx.png` + `xxx.txt`（编辑器导出的、别的模组里的都行），
   把它们读回来继续改：帧名、矩形、排版、再加图；
3. **自动排版** —— 按每个 sprite 的 `W/H` 重新摆位置：书架式（按高度从大到小，一行一行往右摆），
   画布自动选 64/128/256/512/1024/2048 里**装得下的最小方形**，间距默认 2px（防采样外溢）；
   排不下会提示删几块或调小 `W/H`；
4. **切块**：`按网格切分` 把整张画布按 `2 × 2` 之类的网格切开（名字默认 `图集名_01`、`_02`…），
   也可以 `＋ sprite` 手动加、`整张图` 加一整块；每行的 `X/Y/W/H` 是像素矩形（左上角原点，可手改，越界会自动夹回去）；
5. **起名**：每块的 `sprite 名` 就是导出的帧名，也是游戏里 `Futile.atlasManager.GetElementWithName` 用的 element 名 ——
   改了名字，已经套用它的三角形 / 自由贴图会跟着改；
6. **图集名**：只有一个输入框 —— 因为游戏按 **`<名字>.txt` 找 `<名字>.png`**，两个文件必须同名；
   改完下面会显示将要导出的两个文件名；
7. **导出 PNG + TXT**：Chrome / Edge 会让你选一个文件夹，一次写三个文件
   （`<名字>.png`、`<名字>.txt`、`customtail-autoload.json`）；
   其它浏览器退化成三个下载（可能问一次「允许多个下载」）。

<img src="editor/ui-preview-temp-atlas-edit.png" width="300" alt="临时图集面板：插入 PNG / 打开图集 / 自动排版，sprite 列表与导出">

排版会**真的搬像素**：每块从旧画布上按自己的矩形抠下来、画到新位置，所以导出的 png 和 txt 永远对得上。
（画布是同步可绘制的 canvas，连着插好几张图也不会读到"还没解码完"的空图。）

导出的 txt 是 `atlases/` 里那种 TexturePacker **hash** 格式：

```json
{"frames":{"tail_01.png":{"frame":{"x":0,"y":0,"w":32,"h":16},"rotated":false,"trimmed":false,
  "spriteSourceSize":{"x":0,"y":0,"w":32,"h":16},"sourceSize":{"w":32,"h":16}}},
 "meta":{"image":"TailSheet.png","size":{"w":64,"h":32},"scale":"1"}}
```

把这三个文件放进 `mods/<你的模组>/atlases/` 就完事了：CustomTail 启动时会**自动注册**带标识的文件夹里的图集
（见下一节），之后 `element` 填 sprite 名就能在游戏里用（`atlas = true`）。
不想自动注册就关掉导出面板上的 **写入自动注册标识**，自己 `LoadAtlas("atlases/<名字>")` 一次也一样。

- 注入的 PNG 只在当前页面里，刷新就没了 —— 要留下就导出（导出的文件也能再用
  **打开图集…** 或图集页的 **载入图集文件…** 选回来，继续改）。
- 临时图集在「来源」里是 **临时** 一栏，sprite 会和游戏图集一起出现在下面的网格里，点一下就能套用；
  「清空」只把它从图集库拿掉，已经套上去的面仍按原来的矩形显示（想再改就重新插入那张 PNG）。
- **重名会被提前拦下**：sprite 名和本体 / 内置图集里的 element 重名时，导出按钮会拒绝并写明是哪个图集的哪个名字
  （游戏 `FAtlasManager.AddAtlas` 碰到重复 element 名会直接抛异常，会把别的图集一起带崩）。
  和**模组**图集重名只警告不拦 —— 那个模组不一定启用。

### 图集自动注册（`customtail-autoload.json`）

游戏只认启用中的模组，而且图集默认要模组自己 `LoadAtlas` 一次。CustomTail 在 `OnModsInit` 时替你做这件事：

- 扫 `ModManager.ActiveMods` 里每个模组的 `atlases/`（含子文件夹），找 **`customtail-autoload.json`**；
- 找到就把**同一个文件夹里**的每个 `*.txt`（+ 同名 `*.png`）注册成图集，图集名就是模组内相对路径
  （`atlases/TailSheet`，和手写 `LoadAtlas` 完全一致）；
- **跳过**：已经注册过的同名图集（别的模组自己加载过 / 本体就有）、元素名和已有 element 重复的、
  没有同名 png 的、读文件失败的 —— 都会在 BepInEx 日志里写明白；
- 标识文件里写 `"autoRegister": false` 就不注册这个文件夹；删掉 json 也行；
- 按 **F9**（重载 tailmesh）会顺带再扫一遍，新导出的图集不用重开游戏。

```
mods/你的模组/atlases/
├─ TailSheet.png              ← 编辑器导出的贴图
├─ TailSheet.txt              ← 编辑器导出的帧数据
└─ customtail-autoload.json   ← 标识：这个文件夹里的图集自动注册
```

- 只扫**启用中**的模组：游戏的 `AssetManager.ResolveFilePath` 只在 `ModManager.ActiveMods` 目录里找文件，
  禁用的模组根本加载不到。
- 想彻底关掉自动扫描：BepInEx 配置 `CustomTail → Auto register atlases` 关掉。
- 为什么还要提前查重名：`FAtlasManager.AddAtlas` 遇到重复 element 名会抛 `FutileException`，
  而且是在遍历到那一帧时才抛，等于把这一张图集的加载过程截断 —— 所以宁可跳过并写日志。

## 滚转：整条尾巴（连同上面的一切）一起转

尾巴是一根二维的带子，但真实的尾巴会绕自己的轴滚。滚转是**一个整体值** `roll ∈ [-1, 1]`：

| roll | 角度 θ = roll·π | 效果 |
| --- | --- | --- |
| `0` | 0° | 不滚 |
| `±0.25` | ±45° | 侧向压到约 71% |
| `±0.5` | ±90° | 截面正对镜头，压成一条线 |
| `±1` | ±180° | 翻到背面（左右镜像） |

**它作用在整个点线结合体上**，不只是那些直接绑在尾巴上的点：

```
对每个点 P（绑定的 / 派生的 / 自由的都算）
  找离 P 最近的那一节尾巴 → 基准点 Q、沿轴 along、侧向 perp
  显示位置 = Q + 轴·along + 法线·(perp · cosθ)
  进深     = perp · sinθ            （>0 朝观众，<0 转到背面）
```

- 各体节只提供**自己的中轴方向**（`tail` 用段方向、`tvert` 用站点方向、自由点用离它最近那一节），
  角度全程是同一个 θ。所以沿弯曲的尾巴看，整片皮是绕自身曲线连续扭转的，不会错位、也不会被撕开。
- 站点边缘那两个网格顶点本身就是 `perp = ±w`，所以**整条截面一起收窄/翻转**。
- **物理和解算完全不受影响**：`resolveBound()` 一直在平面里算，滚转只在渲染前做一次投影。
  导出的 JSON 里也只有 `tailRoll` 一个数，几何由它推导 —— 同一份文件在编辑器里和在游戏里看到的形状一致。

**游戏里的滚转是逐帧推算的，不是常量**

编辑器里那个 `tailRoll` 只是**基准偏置**；运行时每帧再叠加一项由**状态**算出来的角度。判定顺序（先命中先算）：

| # | 状态 | 权重 | 方向 |
| --- | --- | --- | --- |
| 1 | 趴地 / 爬行 / 趴墙沿（`bodyMode` 含 Crawl） | 满额 1 | 朝向 ±1 |
| 2 | 贴墙（`WallClimb` / `ClimbOnWall`） | 满额 1 | 朝向 ±1 |
| 3 | 钻管道 / 被电 / 死亡 | 0 | — |
| 4 | **杆子上 / 杆子下沿 / 挂边缘 / 悬空**（见下） | `clamp01(|v⊥| / 2.5)` | **`v⊥` 的正负** |
| 5 | 特殊动作：翻滚 / 肚滑 | 满额 1 | `rollDirection` / `slideDirection` |
| 6 | 其它特殊动作（攀、游、吞咽、被抓、昏迷…） | 0 | — |
| 7 | 有方向键：水平位移 > 0.2 | 满额 1 | 朝向 ±1 |
| 8 | 有方向键但没位移 | 0 | — |
| 9 | 无方向键 | `clamp01(|v⊥| / 2.5)` | **`v⊥` 的正负** |

`v⊥` = **bodyChunk[1] 的速度在"身体垂线"方向上的分量**（脊柱 = 躯干 − 臀部，取它的法向）：

```
v⊥ = −dot(hips.vel, normalize(perp(body − hips)))      // 站直时 ≈ 水平速度，朝右为正
roll = clamp( tailRoll + sign · RollMax · weight , −1, 1 )
sign = 特殊动作方向 > v⊥ 的正负 > flipDirection   （最后再按 "Roll invert direction" 取反）
```

**第 4 条的判定**（`MeshInstance.VelocityDrivenRoll`，有单测）：

- `bodyMode` 名字含 `Beam`（`ClimbingOnBeam` / `ClimbOnBeam`…）；
- 动画是 `HangFromBeam` / `HangUnderVerticalBeam` / `ClimbOnBeam` / `GetUpToBeamTip` / `BeamTip` /
  `LedgeGrab` / `LedgeCrawl` / `AntlerClimb` / `GrapplingSwing` / `VineGrab`；
- **悬空**：脚离地（`lowerBodyFramesOnGround == 0` 且臀部无地面接触）**且不在水里**。

也就是说：在杆子下沿、挂在边缘、或整个人腾空时左右摇摆，滚转**完全由身体侧向速度决定** ——
不看朝向、也不看方向键；朝右漂是正角、朝左漂是负角，漂得越快越接近上限，停住就回 0。
速度穿零的一瞬间会沿用上一次符号 0.2 s，避免符号闪回朝向。

- **诊断**：配置项 `Roll debug`（默认开）每秒往日志打一行
  `滚转统计：roll 12~74°，…，mode Default，来源 velocity:+2.13，权重 0.85`。
  `来源` 会写明走的是哪条分支：`pose` / `blocked:` / `veldrive(HangFromBeam):-1.80` /
  `special:Roll dir=-1` / `input` / `velocity:+2.13`。定位完可以关掉。
- 上限是配置项 `Roll max angle`（`BepInEx/config/CustomTail.cfg`，默认 75，0 = 完全不滚）。
- 站直不动时恒为 0，花纹完全按编辑器里画的样子显示。
- **翻过 90° 换层**的机制仍然保留（`SwapNeeded` / `Reorder`）：上限 75° 时不会触发，
  但把上限调到 90° 以上时，背/正面层会自动对调，不会出现花纹浮在尾巴上。

### 为什么以前"滚转角一变，线长就跳一下、还不稳"

投影要先把平面点分解成「沿轴 + 侧向」，而分解用的轴原来是**离它最近那一节的轴**。
这个选择是**分段常数**：点一越过两段的分界，法线就整块换掉，而投影恰好是

```
显示位置 = 平面点 + (cosψ − 1) · 垂直偏移向量
```

偏移项用的正是那条法线，于是换段瞬间就跳一下。ψ = 0 时这一项恒为 0，所以**站在正面看不出来；
滚转角越大跳得越狠**，幅度 ≈ |Δ法线| · |perp| · |1 − cosψ|。实测（尾巴半宽约 1.5 世界单位）：

| 离轴距离 | roll=0 | roll=60° |
| --- | --- | --- |
| ≤ 2 | 0 | 0.32 |
| ≤ 5 | 0 | 0.84 |
| ≤ 11 | 0 | 1.87 |
| 全画布最坏 | 0 | 2.91 |

尾巴在动、点也在动，于是每次越界都"顿"一下 —— 看起来就是线长忽长忽短、不稳。

**修法（两侧逐行一致）**

1. **按弧长做单位分解**，不再"取最近那一节"（编辑器 `rollFrame()` ↔ 运行时 `FrameBlend()`）：
   先求点的弧长坐标 u，段内权重恒为 1（≡ 只用自己那一节，**与老行为逐位相同**），
   只在关节两侧各 `FRAME_BLEND = 1.0` 个弧长单位内与邻段平滑过渡；
   u 本身在"几段几乎等距"时做软平均，模糊带随离轴距离放大（远场才连续）。
2. **滚转角本身限抖**（`ComputeRoll`）：`flipDirection` 迟滞 0.08s + 符号指数平滑；
   姿态在"头贴近髋"时用 smoothstep 渐隐（原来是 `sqrMagnitude > 16` 的硬门限，一过线就整块切 0）；
   roll 按真实 dt 做指数平滑并限速（≈ 7×上限/秒），转身不会连着几帧猛扫。

结果：同场景最大跳变 **2.91 → 0.22**，尾巴附近 **0.84 → 0.024**，ψ=0 时仍然逐位不变。
回归脚本 `tooling/roll_smooth.js`（9 项）盯住这几条：ψ=0 恒等、跨段无台阶、
段中间仍精确绕自己那节的轴、跨关节不顿、直尾巴长度严格 = 原长·cosψ。

**怎么实现的（两边必须一致）**

| | 编辑器 | 游戏 |
| --- | --- | --- |
| 投影 | `warp(p)` / `rollFrame(p)` | `MeshInstance.Project()` |
| 用在哪 | 画布、命中测试、框选、贴图 | `DisplayPositions` → `TriangleMesh` 顶点 |
| 拖动 | `unwarpDelta()` 把屏幕位移 ÷cosθ 换回平面 | — |

- **遮挡**：进深 <0 的那半边在背面，应该被尾巴本身挡住。RW 是 2D、没有深度缓冲，
  唯一的深度手段就是容器里的绘制顺序，所以两边都用同一套层序：
  编辑器把背面那组整组画在尾巴**下面**（被实色尾巴盖住，只有探出轮廓的部分可见）；
  游戏侧把背面层插在尾巴精灵**之前**、正面层插在**之后**（`FindTailSpan` 先按 element 名里带
  "Tail" 的精灵找出尾巴在容器里的下标区间，找不到才退回老假设 `sprites[2]`）。
- 拖动时鼠标位移会按 `1/cosθ` 反投影回平面，所以画布上拖到哪、点就落到哪；
  `|cosθ|` 很小时（截面几乎正对镜头）侧向不再放大，避免一点就飞出去。

> JSON 里是 `physics.tailRoll: 0.42`（一个数）。早期版本误存成数组，读取时取平均兼容。

## 绕轴分层：`wrap`

尾巴是个圆柱，只在正面平面上画，侧面就永远是一条线。所以每个节点还带一个**绕轴角 `wrap`**（度，15° 的整数倍，缺省 0）：

```
ψ = wrap + roll·180°          （游戏里没有"编辑视角"，cam 恒为 0）
屏幕侧向 = perp · cosψ
进深     = perp · sinψ
```

- 编辑器左下角的罗盘就是把视角绕轴转过去：转到哪个角度画，画出来的点就记在哪个角度上（`wrap = cam − roll`）。
  所以在 45° 画的东西，永远和正面差 45°。
- `wrap = 0` 时与没有这一维逐位一致；这个字段只在非 0 时才写进 JSON，旧文件不受影响。
- 和 `roll` 的分工：`roll` 是**尾巴自己的姿态**（导出到 JSON、游戏里生效），`wrap` 是**装饰装在哪一圈**。
  两者都进 ψ，所以拧滚转时所有层一起转。
- 不同角度之间**不能连线、不能成面**，只共享**尾巴基准点**（`bind.kind = "tvert"`、偏移 `0,0` 的那 9 个，
  编辑器自动补齐、不能移动/删除）。基准点本体钉在正面不动，但每个角度有各自的"视觉克隆体"：
  线/面连到的是 `ψ = 该层角度` 投影出来的位置（`DisplayFor()` ↔ 编辑器 `dispIn()`）。
- 每层是贴上去的一块**硬板**：从别的角度看会透视缩短（45° 层在正面只剩 71%），恰好 90° 的层正面不可见。
  窄长装饰没问题，别指望大面积图案能连续绕身。
- **自由贴图**（`sprites[]`）的位置点如果是**锚点**（尾巴基准点或身体块 `body0/body1`），层角用它自己的
  `wrap` —— 左右翅膀各占一层（比如 -45° / -135°）就能各转各的；位置点是普通点时，跟随那个点的层。
  编辑器、游戏渲染、暂停菜单预览三处用的是同一个判据（`spriteWrap` ↔ `MeshInstance.SpriteWrap`）。
  > 以前游戏端只认尾巴基准点，挂在身体块上的 sprite 会被当成 0° 层：两边的翅膀算出来几乎同一个四边形，
  > 看着就"只剩 scale 为正的那一边"。

> 编辑器里把罗盘转到 0° 再导出，游戏里就是同一个形状 —— 两边 `ψ` 公式等价，只有 `cam` 在游戏里恒为 0。

### 编辑器 ↔ 运行时的三个对齐点

这三处如果对不上，游戏里的形状就会和编辑器里看到的差一截（不是角度问题，是初值/约束问题）：

1. **静息长度取 `links[].rest`，不是"两个 rest 坐标的距离"**。节点被拖动过之后这两者会不一样，
   而编辑器用的是前者（`restLen()`）。JSON 里没有 `rest` 的老文件才退回几何距离。
2. **自由点的出生位置**。`nodes[].rest` 是**编辑器世界坐标**，原点在编辑器的尾巴根
   （`joints[0]`，由 `body.hip + body.off/4` 决定，默认 `(0.75, 4.25)`）。
   运行时要用 `joints[station] + (rest - 编辑器尾巴根)`，直接 `joints[0] + rest` 会把这段偏移算两遍，
   出生时整体偏一截、要靠弹簧扯几帧才回位。编辑器尾巴根从站点 0 两个基准点的 rest 中点反推。
3. **进深符号必须在解算之后算**。`NodeDepthSigns()` 会在建层时把三角形分到背面/正面层；
   如果这时自由点还没跑过一帧解算，它们的进深全是 0，画在背面的装饰会被错分到正面层（浮在尾巴上）。

## 编辑器

`editor/tailmesh-editor.html`（双击打开，无需联网）：

界面分四块：**顶栏**（撤回/重做、暂停、重置、打开、保存、导出模组）、**左栏工具栏**（按 选择 / 创建 / 编辑 / 尾巴 分组，
每个工具带快捷键角标）、**中间画布**（左上角是 点/线/面/顶点/尾巴 图层开关，右下角是缩放与"适应视图"）、
**右侧检查器**（属性 / 物理 / 尾巴 / 图集 四个页签）。

- 左侧工具：选择/拖动 `V`、施力拖动 `F`、加点 `P`、连线 `L`、三角形 `T`、绑定 `B`、删除 `X`
  （"设为静止形状" = 把当前形状写回 `rest`）；
- **两种拖动语义**，别混了：
  - **选择/拖动** = 编辑形状：点跟着鼠标走，并把相邻边的静息长度同步成新距离，松手不回弹，形状就是你想要的；
  - **施力拖动** = 给点施加力：每步把点朝鼠标拉`牵引比例`（物理面板可调，默认 0.3），
    **不写 `link.rest`、不写 `rest`**，所以线长保持原样、网格靠距离约束自己拉回来；松手保留速度，
    会自然回弹甚至甩出去。画布上会显示一条牵引线；
- **尾巴也会受力**（编辑器内）：施力拖动可以直接抓**尾巴网格顶点**（站点 0–4），力会加到它覆盖的尾巴节上；
  反过来，线的距离约束作用在绑定点上时，被"推走"的那部分会按 `0.5` 的耦合转成尾巴节的外部推力
  （`solve()` → `pushTailSeg()` → 下一帧 `stepTail()` 消费），所以拉一张细挂在尾巴上的网，尾巴会被拽着走；
- **所有数值都能直接输入**：滑条右边的数字框可以直接打字（回车/失焦生效，自动夹到范围内）；
  节点面板有 `X/Y/静止X/Y`，**尾巴**页签有每节的 `rad / connectionRad / affectPrevious`、整体滚转、髋偏移、默认线宽；
  > 尾巴页签里的这三个值是**编辑器预览用**，不写进 JSON —— 游戏侧直接读 `graphics.tail[i]`。
  > 想让编辑器里的形状和游戏一致，就别把它们改得和模组配置里的 `TailSegment` 差太远，
  > 否则按编辑器形状调出来的 `local` 偏移到游戏里会偏。表里显示为虚线的格子（尾根的 `affectPrev`、
  > 尾尖的 `rad`）当前不参与计算，悬停有说明。
- **多选**：空白处拖 = 拉框选点，**Shift+点击** = 增减（也认 Ctrl），`Ctrl+A` 全选；多选后拖动会整组平移
  （组内的线保持长度，跨组的线同步成新长度）；
- **撤回 / 重做**（`Ctrl+Z` / `Ctrl+Y`，`Ctrl+Shift+Z` 也是重做）：快照式，覆盖加点、连线、三角形成面/删面、
  拖动改形状、施力拖动、删除、粘贴、改绑定、套贴图、改尾巴/物理参数；空点一下不会产生撤回步（比对后再入栈），
  最多 120 步，做新操作会清空重做栈；
- 画布上带编号的青绿色小方块就是**尾巴网格顶点 0–9**（见上一节），只读、只能被绑定：
  选中点后用绑定工具点它们，或右侧"绑定 → 尾巴网格顶点"；已绑上的顶点显示实心；
- "导入尾巴顶点" 把这 9 个顶点直接变成可编辑节点（尖部两点重合只建一个），方便沿着轮廓搭装饰；
- 拖动**髋部圆圈**可以把身体挪动，尾巴会像游戏里一样甩；
- 选中点后右侧可以切绑定方式（尾巴网格顶点 / 尾巴任意位置 / 某个点 / 某条线的百分比）并微调偏移；
- 选中线可以调 `stiffness`（1 = 刚体）；
- 选中三角形后右侧套贴图：点 **「从图集选择…」** 跳到图集页签挑一个 sprite（本体/模组/AB 包的都能挑），
  sprite 自带贴图和像素尺寸，`element` 自动填好，画布上立刻能看见真实贴图；
  也可以手填 `element` 后点「按名字匹配」，或直接调 UV 矩形、载入一张临时预览图；
  Shift+点击多选后点 **「合并选中为同一组」** 就把几组合并成一张图；「选中同组」可以按贴图反选回来；
- 选中**自由贴图**后左侧属性栏可以改 位置点 / 方向点 / 锚点 / 尺寸 / 角度；
  `scale` 支持负数（负 = 镜像翻转），也有「水平翻转 / 垂直翻转」两个按钮，
  填「宽 px / 高 px」只改大小、不会把镜像掰回来（`0` 会被忽略，不会把 sprite 压没）；
- 「朝向」里有 **不旋转（不跟随滚转）**：勾上之后这个 sprite 完全按**屏幕/平面**画 ——
  **滚转、层角压缩（cosψ）、层角偏移都不参与**，位置直接取位置点的平面坐标，朝向只由 `angle` + 方向点决定。
  所以它不会跟着走路一起翻/被压扁，**同一个位置点上的两个不旋转 sprite 会严丝合缝地叠在一起**
  （光环这种由前后两半拼成的装饰就靠这个）；它不参与前后遮挡，**固定画在玩家最上面** ——
  只插在"尾巴之后"是不够的：Slugcat 的头等部件在 `Foreground` 容器里，那个容器整块画在
  `Midground` 之后，光环会被头整个盖住。所以不旋转层会被放进 `Foreground` 的**末尾**
  （换容器前会核对坐标系，不一致就退回尾巴容器）。
  JSON 里是 `"noRoll": true`；
- 画布左上角 **点 / 线 / 面 / 顶点框 / 尾巴 / 自由贴图 / 身体圆** 七个开关控制显示什么
  （只看贴图效果时可以把点线关掉，隐藏不影响拾取；「自由贴图」关掉后 sprites[] 既不画也选不中）；
- 顶栏 **打开** / **保存** → 导出的 `tailmesh.json` 放进 `mods/CustomTail/tailmesh/`；
- 画布右下角可以缩放、点「适应视图」一键把所有点和尾巴框进画面。

### 项目文件（打开 / 保存 / 另存为 / 新建）

编辑器把「一个 `.json` 文件」当成一个项目：**保存直接覆盖打开的那个文件，不再下载**。

| 按钮 / 键 | 行为 |
| --- | --- |
| **新建**（`Ctrl+N`） | 清空成新项目（自动补尾巴基准点/身体锚点），断开文件关联；有未保存改动会先确认 |
| **打开**（`Ctrl+O`） | `showOpenFilePicker` 选文件 → 读入 → **记住这个文件句柄**，状态栏提示「Ctrl+S 直接覆盖」 |
| **保存**（`Ctrl+S`） | 有句柄 → 就地覆盖（`createWritable`）；没有句柄 → 自动转「另存为」 |
| **另存为**（`Ctrl+Shift+S`） | `showSaveFilePicker` 选新位置，之后保存就写到新文件 |

- 顶栏左侧显示**当前文件名**：实线边框 = 已关联文件，虚线 = 还没关联；有未保存改动会亮琥珀色圆点，浏览器标题也变 `● 文件名 — CustomTail`，关页面前会提示。
- 文件句柄存进 **IndexedDB**：刷新 / 重开这个页面后，顶栏会出现 **「继续：xxx.json」**，点一下就直接接上（浏览器会再问一次写入权限）。找不到旧文件就还是用「打开」。
- 只认 Chrome / Edge 的 File System Access API（**双击 `file://` 打开也能用**，实测 `isSecureContext` 为 true、两个 picker 都在）。
  其它浏览器自动退回旧行为：**打开**走 `<input type=file>`，**保存**变成下载，并在提示里写明"已改为下载"。
- 保存时如果还有点在非 0° 层，提示里会带上「游戏端尚未同步」的提醒。
### 贴图 / 三角形的统一（左栏「三角形组」+「自由贴图」）

以前"贴图"和"三角形"是两套各管各的面板，点图集会把贴图直接套到三角形上，选中 sprite 时又不知道该套哪儿。现在统一成**一个"当前贴图"**：

| 位置 | 作用 |
| --- | --- |
| 左栏 **贴图** 组里的「当前贴图」徽标 | 一眼看到当前用的是哪个 sprite；点它直接进**图集** |
| 属性面板顶部常驻的「当前贴图」条 | 显示缩略图 + **作用对象**（当前 sprite / 选中的 N 个面 / 新对象）+「换…」 |
| 面板里的「贴图组」快捷条 | 列出所有贴图组，点一下切换（对当前选中对象生效） |
| 左栏 **三角形组（T）** | 点 3 个点成面，**新面直接归到当前贴图组**，不用再去点一次"套用" |
| 左栏 **自由贴图（S）** | 用当前贴图在画布上**点一下就放一个 sprite**；点在已有点上就锚在那个点，点空白会自动建位置点 |

在**图集**里点一个 sprite 时，按"当前选中什么"分流：选中 sprite → 换这个 sprite 的贴图；选中面 → 套到这些面；什么都没选 → 只记住当前贴图，接着用左栏两个工具去创建。


### 为什么"保存再打开"以前会丢贴图

`textures[]` 里只写了 `element` 名字，编辑器要靠图集库把这个名字解析成"图集里的哪一块"。
如果重开时图集库还没载入（或换了一台机器），解析不到 → 三角形/sprite 全变纯色，看着就是贴图丢了。

现在做了两件事，彻底不依赖"重开时图集库刚好在"：

1. **导出时把每一帧的像素内嵌进 JSON**（`textures[].img` = 裁剪好的 data URL，通常几 KB；
   同时写 `textures[].lat` 记录来源图集）。重开时直接把它当整帧图用，`ar = 整图`。
2. **图集库变化后自动重挂**（`libResyncSoon()`）：新增图集、或图片异步到货时，
   会把已打开文件里"只有 element 名字"的贴图重新挂上并重绘。

老文件（没有 `img`）依然能从图集库按 element 名找回，行为不变；`img` 只影响编辑器预览，游戏端只读 `element`。

### 「贴图组」列表怎么用

属性面板里的「贴图组 · 点一行切换」现在是**一行一个组**：缩略图 + 组名 + 这张图**用在几个面上**，
当前组带绿色「当前」标记，其它行显示「切换」；点一行 = 设为当前贴图（选中了面就顺手套上去）。
最后一行是 **＋ 新组**（建一个空组，再去【图集】点一个 sprite 填图）。
### 选点模式（不用"先选中再去点按钮")

需要指定"用哪个点"的地方（sprite 的位置点 / 方向点 / 新建 sprite 的位置），现在都是：
**点面板上的按钮 → 画布顶部出现蓝色提示条 → 直接在画布上点一下**：
- 点到已有的点 → 直接填入；
- 点到空白 → 在那个位置**新建一个点**再填入（省掉"先加点再选它"）；
- `Esc` 或提示条上的「取消」退出。

### 图集：按模组筛选 + 所有 sprite 平铺

- 「来源」chips 之上新增 **模组** 下拉：`全部模组（N 个 / M sprite）` + 每个模组（含图集数、sprite 数），配合「来源」「图集」「搜索」四个筛选一起用；
- 下方网格把匹配到的 sprite **逐个切片平铺**（带缩略图与名字），当前贴图高亮；点一下就套用/设为当前贴图。

## 游戏内运行

每帧：先把绑定点算到实时尾巴上，再让自由点做 Verlet 积分；每轮迭代里 **距离约束（links）+ 角度约束（angles）** 交替求解（PBD），
然后按每层自己的 ψ 投影，写进对应的 `TriangleMesh`。一个 doc 一帧只解算一次，
背面/正面两层共用同一份结果。

容器顺序是 `背面层 → 尾巴精灵 → 正面层`，所以**尾巴能挡住跑到它后面的贴图**；
尾巴精灵不可见时（死亡、过场）网格一起隐藏。层数 = 每个贴图组 × 前后。

暂停菜单里的 **TAILS → 预览** 用同一套几何（4 节尾巴物理 + 同一个 `MeshInstance`）重画一遍角色、尾巴和装饰：
三角形和**自由贴图**都会画出来，滚转滑块拖到哪，预览里就是游戏里那副样子。

所有 `PlayerGraphics` 都会挂上（不分蛞蝓猫种类，测试期先全开）。第一次进房间时会在日志里打一条
`[CustomTail] sprites：0=…, 1=…` 的下标名单，用来确认哪几个是尾巴精灵。

按 **F9** 重载 JSON：下帧就地在房间里重建，不用退房间（`Generation` 变了 `Draw` 里会自己 `Rebuild`）。

### TAILS 界面：打开即重扫 + 两个快捷按钮

暂停菜单 → **TAILS** 每打开一次都会**重新扫一遍磁盘**（图集标识 + `tailmesh/*.json`，含别的启用模组），
所以往文件夹里丢一份新 json、或者编辑器刚导出了新图集，直接重开界面就能看到，不用按 F9、也不用退房间。

底部一排按钮：

| 按钮 | 作用 |
| --- | --- |
| `RELOAD JSON` | 手动重扫（和 F9 一样） |
| `CLEAR` | 清掉当前目标的绑定 |
| `OPEN FOLDER` | 打开模组根目录（`mods/CustomTail`：`tailmesh/`、`atlases/`、`tailbindings.json` 都在这儿） |
| `OPEN EDITOR` | 打开编辑器 `editor/tailmesh-editor.html`（默认浏览器）；没有这个文件就打开 `editor/` 文件夹 |
| `CLOSE` | 关掉界面 |

> 两个 OPEN 按钮走 `cmd /c start "" "<路径>"`，所以文件夹交给资源管理器、html 交给默认浏览器；
> 路径是用 `MeshStore.Root` 现算的，游戏装在哪个盘都能用。

### 扫描其它模组的 `tailmesh/`

不只读自己的目录：启动时会把**所有启用中模组**（`ModManager.ActiveMods`，和自动注册图集用的是同一份列表）
的 `tailmesh/` 也扫一遍（含子目录），所以别的模组可以直接往自己文件夹里丢网格，不用复制进 CustomTail。

- **键名**：默认仍是 `tailmesh/` 下的相对路径（`mytail`）。两份文件重名时，后加载的那份自动改名成
  `mytail@模组文件夹名`，并写一条日志；
- **编码**：读文件走 `Json.ReadText()`，自动认 BOM / 严格 UTF-8 / 本地 ANSI（GBK）——
  别的模组用 GBK 存的 json 也能正确读出中文（以前 `File.ReadAllText` 按 UTF-8 读成乱码还不报错）；
- **默认不生效**：别人模组的网格**不参与**"没被任何规则点名就套给所有玩家"的兜底 ——
  否则你装个带 `tailmesh` 的模组，尾巴就被别人顶掉了。要生效得在 `tailbindings.json` 里点名；
- **绑定表也会合并**：每个启用中的模组都可以在自己根目录放一份 `tailbindings.json`，
  里面的规则当**默认值**（自己的文件后加载，同分时自己赢）。菜单保存时**只写自己的规则**，
  不会把别人的规则抄进自己的文件；`Remove` 也删不掉别人的默认值。

想给某个模组做适配，它只要这样放：

```
OtherMod/
  modinfo.json
  tailmesh/悬浮尾.json        ← 网格
  tailbindings.json          ← { "rules": [ { "tail": "悬浮尾", "slugcat": "Spearmaster" } ] }
```

### 缺贴图 → 绿色方块

JSON 点了一个图集里不存在的贴图（图集没装 / 名字打错 / 那个模组没启用）时，
不再退回"白方块 + JSON 颜色"那种看不出来的样子，而是统一退化成**亮绿色方块**（32×32），
游戏里和 TAILS 预览里表现一致，一眼就能认出"这里缺贴图"。日志里每个名字只提示一次：

```
[CustomTail] 贴图「rim3」不在任何图集里，退化成绿色方块（同一张只提示一次）。
```

> 实现：`TexFallback`（`src/Mesh/MeshRenderer.cs`）。三角形组、自由贴图、预览里的花纹网格都走它。

> 注意：**"尾巴受力"目前只在编辑器里**。游戏里的尾巴由 `PlayerGraphics` 自己驱动，模组只读它的关节位置，
> 不去改 `TailSegment`（否则会和原版尾巴打架）；所以编辑器里被拽动的尾巴，导出后在游戏里不会真的被拽。

### 模组封面

`mod/thumbnail.png`（1600×900，16:9，游戏模组列表直接用它）是**纯代码画出来的**，没有外部素材：
`tooling/make_cover.py` 用 numpy + Pillow 生成 ——

- 背景：竖向渐变 + 两团光晕（尾巴后面一团青色、左下一点暖色）+ 暗角 + 很淡的点阵；
- 尾巴（右侧）：Catmull-Rom 中心线 → 沿曲线盖椭圆得到蒙版 → **FFT 高斯模糊当高度场、取梯度做伪法线**，
  和光照方向点乘出圆管的明暗（比"叠几层色带"干净，也不会像 8 位模糊那样出现一圈圈等值线）；
  末端 12% 收成尖，再加几条分段线暗示 `TailSegment`；
- 尾巴身上的点线：沿尾脊 5 个站点 × 左右两个锚点 —— 青色连线 + 琥珀方块，其中一个带白圈表示"选中"；
- 底部三角网格（**红色**，每个顶点一个圆点）：**不是程序生成的**，而是从手绘草图里抠出来的 ——
  `tooling/sketch_to_mesh.py` 把草图里的红色笔迹做阈值 → 闭运算补缝 → 从 (0,0) 洪水填充找出所有"被红线圈起来的
  内部区域" → 每个区域取凸包上面积最大的三点 = 三角形的三个角 → 外扩半个线宽回到笔迹中线 →
  再把距离 <14px 的角**并成同一个顶点**（weld）。输出 `VERTS` + `FACES` 两段贴进 `make_cover.py`，
  所以位置、大小、朝向和手绘图逐点一致，而且**相邻三角形共用顶点 = 共边**：
  画的时候按顶点对去重，共边只画一条线（不会出现两条线叠在一起发黑）；
  配色是**按 x 的渐变**（靠尾巴那头暖金 → 中段橙红 → 左边深红），所以整片网格像被同一盏灯照着；
  每条边分三段画：暗面（右下偏移）+ 主体 + 高光（左上偏移），再加上一层模糊辉光和一层落地投影，
  线就有了"圆条"的厚度、网格也浮在背景上；顶点圆点用当地的颜色提亮；

- **对齐尾巴上的点**：`_snapped_verts()` 会把距离尾巴锚点 34px 以内的三角形顶点**吸附到锚点上** ——
  也就是尾巴那 5 个站点 × 左右两个琥珀方块（`tail_anchor_points()` 一处算，尾巴点线和网格共用），
  连到尾巴的那几个三角形顶点因此和尾巴上的点完全重合；
- 文字只有三行：橙色小标 `RAIN WORLD · 3D TAILMESH EDITOR` + `CustomTail`
  （Segoe UI Black，按宽度自动缩放）+ 中文副标题「尾巴网格编辑器」（微软雅黑）。
  缩略图缩到 320×180 也读得出来。

想调就改这些常量：

| 想改什么 | 改哪儿 |
| --- | --- |
| 红色三角形的位置 | `VERTS` / `FACES`（重新手画一张草图后跑 `sketch_to_mesh.py` 重新抠，再整段替换） |
| 尾巴走向 / 粗细 | `CTRL`（控制点）、`RADIUS`（各点半径） |
| 尾巴上的点线 | `tail_mesh()` |
| 颜色 | 顶部调色板 / `MESH_RED` |
| 文案 | `draw_text_block()` |

## 已知限制

- 自由点是纯被动弹簧结构：只有两个锚点时，重力会让三角形绕锚点转到最低点，这是物理上正确的行为；
  想要形状固定就多绑几个点或把线设成刚体。
- 网格不参与物理碰撞，不会被地形推开。
- 尾巴本身仍是游戏的画法，模组只增加额外的三角形。
